## Demande

- monorepo pnpm ;

## Décisions et pourquoi

- **SvelteKit 3.2** au lieu de la 2 prévue dans le plan : version stable depuis octobre 2026. `adapter-static` 4 et `@vite-pwa/sveltekit` 2 l'exigent.
- **TypeScript 6.0.3** : `typescript-eslint` 8.72 n'accepte pas TS 7. **Vitest 4.1** : `@cloudflare/vitest-plugin` exige `^4.1 || ^5`, et la 4 est alignée sur le reste.
- **`@cloudflare/vitest-plugin`** à la place de `@cloudflare/vitest-pool-workers`, déprécié et renommé.
- **Mode dev limité** : `DEV_USER_EMAIL` n'est honoré que si `ACCESS_AUD` est absent, ce qui protège contre un oubli en production.
- **RS256 imposé** dans la vérification du JWT : c'est l'algorithme d'Access (point relevé en revue).
- **Polices auto-hébergées** (`@fontsource-variable/outfit`, `@fontsource-variable/inter`) plutôt que Google Fonts, pour l'usage hors ligne de la PWA.
- **`lucide-svelte`** prévu par le plan mais pas installé : aucune icône n'est encore utilisée, il arrivera au lot 1.
- **Manifeste lié en dur** dans `app.html` : en SPA, un `<link>` injecté par `svelte:head` n'existe qu'après le JS.
- **Proxy dev configurable** (`MYTRIPS_API_URL`) : les ports 5173 et 8787 étaient déjà occupés sur la machine par un autre projet (la maquette).

## Bugs et pièges rencontrés

- **`@vite-pwa/sveltekit` 2** :
  - `SvelteKitPWA` a été remplacé par `withPwa(configKit, optionsPwa)` ;
  - `strategies` (et non `strategy`) ;
  - options Workbox sous `generateSW` ;
  - peer dependencies `magicast` et `rolldown` obligatoires (« Magicast is required… ») ;
  - motif `prerendered/**` ajouté d'office, vide en SPA, d'où `globStrict: false`.
  - La doc en ligne du plugin n'est pas à jour : lire `dist/*.d.mts`.
- **SvelteKit 3** :
  - plus de `svelte.config.js`, la config passe au plugin Vite ;
  - `tsconfig.json` doit étendre `$app/tsconfig` ;
  - `$lib` supprimé, remplacé par `#lib` (champ `imports`) avec l'extension `.ts` pour les modules TS ;
  - `svelte-kit sync` échoue tant qu'il n'y a aucune route, et doit tourner avant `vitest` (script `test`).
- **Tests du Worker** :
  - `SELF` est déprécié, on utilise `exports.default.fetch()` de `cloudflare:workers` ;
  - `exports` est typé via `Cloudflare.GlobalProps.mainModule` ;
  - en parallèle avec les autres paquets, le premier appel dépassait 5 s (démarrage de workerd), d'où `testTimeout` à 20 s et `--workspace-concurrency=1` ;
  - le plugin de test charge `apps/api/.dev.vars` : un `DEV_USER_EMAIL` local faisait échouer le test « Access non configuré ». Les tests neutralisent donc `DEV_USER_EMAIL` par défaut, et la suite est vérifiée avec et sans `.dev.vars`.
- **E2E service worker** : `navigator.serviceWorker.ready` se résout dès l'état `activating`, d'où un `expect.poll` jusqu'à `activated`.
- **Heredocs shell** : un heredoc contenant `$lib` ou des apostrophes typographiques a cassé l'analyse bash, sans rien écrire. Pour les fichiers longs, préférer l'outil d'écriture de fichiers.

## Revue

- **Important, corrigé** : `jwtVerify` n'imposait pas l'algorithme. RS256 est maintenant imposé, avec un test ES256.
- **Corrigé pendant les vérifications** :
  - dépassement de délai des tests API en parallèle ;
  - test d'authentification dépendant d'un `.dev.vars` local.
- **Laissé tel quel, volontairement** :
  - un `DEV_USER_EMAIL` invalide sans Access configuré renvoie 500 `access_not_configured` (comportement sûr) ;
  - l'échec éventuel du chargement de `virtual:pwa-register` n'est pas affiché (sans effet sur l'usage).
