# Lot 6 · Randonnées GPX (durée à 3,5 km/h, option D+)

- Date : 2026-11-16
- Type : fonctionnalité
- Issue : #8 (épique #1)

## Demande

Ajouter des randonnées depuis un fichier GPX :

- le départ du tracé est l'arrivée du trajet précédent, et son arrivée le départ du trajet suivant ;
- la durée est estimée à 3,5 km/h, avec une option pour le dénivelé ;
- le tracé et le profil altimétrique s'affichent.

## Décisions et pourquoi

- **Sans R2** (choix de l'utilisateur) : R2 n'est pas activé sur le compte, et l'activer demande un moyen de paiement.
  - Statistiques et tracé simplifié vont dans D1 ; l'original n'est pas gardé.
  - Les colonnes `gpx_key` et le téléchargement prévus sont abandonnés.
- **Analyse dans le navigateur** (repli prévu par le plan) : le Worker gratuit n'a que 10 ms de CPU par requête. Mesure : 50 000 points (4,8 Mo) prennent 1,7 s. L'API reçoit et valide `GpxData`.
  - Pas de `multipart`, donc pas de 413 côté API : la taille est contrôlée à la lecture du fichier (10 Mo).
- **Une seule écriture** pour créer une randonnée depuis un fichier : `StepCreate.gpx`.
- **Durée manuelle** : une durée saisie n'est plus recalculée depuis le GPX. Changer l'option dénivelé recalcule et repasse en automatique : l'utilisateur garde ainsi un moyen simple de revenir au calcul.
- **Fichiers d'exemple générés** (géométrie et dénivelés connus) plutôt que de vrais GPX : valeurs attendues exactes, sans données personnelles.
- **Import par `?raw`** dans les tests de `core` : le paquet n'a volontairement aucun type Node.

## Bugs et pièges rencontrés

- **Texte découpé par les blocs Svelte** : les espaces en bordure de `{#if}` disparaissent. Le résumé GPX est construit en une seule chaîne.
- **Attente e2e erronée** : la boucle d'exemple n'est pas refermée (12,37 km au lieu de 12,4). Elle donne 3 h 30, pas 3 h 35 ; les tests unitaires de durée partent, eux, de statistiques fixées.
- **Annuler l'option dénivelé** : `inverseOps` ignorait `useElevation`, d'où un lot vide refusé par l'API (400). Corrigé, avec un test.
