# Lot 4 · Trajets obligatoires et routage (ORS, Transitous, avion, ferry)

- Date : 2026-11-16
- Type : fonctionnalité
- Issue : #6 (épique #1)

## Demande

Entre deux étapes consécutives, un trajet est obligatoire ; tant qu'il manque, une tuile « + trajet » s'insère entre les deux. On choisit le mode (voiture, vélo, marche, avion, bus, train, ferry), le routeur calcule distance, durée et tracé, et on peut forcer la distance ou la durée. Le tracé s'affiche sur la carte, coloré par mode.

## Décisions et pourquoi

- **Transitous intégré dans le respect de sa politique** (décision de l'utilisateur : il publie le dépôt). Ce qu'elle impose : un projet open source publié, un usage non commercial, un contact dans le User-Agent et un lien vers les sources. Le contact passe par `CONTACT_URL`, sans donnée personnelle en dur.
- **Sans clé ORS ou en erreur : estimation locale** (décision de l'utilisateur), marquée « estimé ». Un 404 d'ORS veut dire « aucune route » : `422 no_route`, puis saisie manuelle.
- **Calcul côté Worker** : le front n'envoie que la paire et le mode. Le Worker retrouve les points (sortie de l'étape précédente, entrée de la suivante), l'heure de départ estimée et le fuseau.
- **Trajets caducs nettoyés juste après l'écriture**, conditionnés à la version (le plan prévoyait la même transaction). Supprimer dans la transaction obligerait à simuler l'état futur des étapes avant d'écrire. Le front n'affiche de toute façon que les paires requises.
- **« Reprendre » côté front** : le trajet saisi à la main et retiré est gardé en mémoire pour la session, puis proposé sur une tuile vide qui touche l'une de ses étapes. Un échange de deux étapes inverse la paire, d'où la recherche sur les deux clés.
- **Cache** : seuls les calculs des fournisseurs sont gardés. Une estimation n'est pas mise en cache, pour qu'une clé ORS ajoutée plus tard serve aussitôt.
- **Éditeur en fenêtre** (le plan prévoyait un panneau latéral), par cohérence avec les autres éditeurs.

## Bugs et pièges rencontrés

- **`new URL('/chemin', base)` efface le chemin de la base.** Avec `TRANSITOUS_URL=http://localhost:8798/transitous`, la requête partait sur `/api/v5/plan` à la racine : 404, puis estimation silencieuse. L'e2e « aucun itinéraire » l'a révélé. Même défaut latent pour Geoapify et Photon : les trois sont corrigés par concaténation, chacun avec son test.
- **Paramètres D1** : mélanger `?1` numéroté et `?` anonymes (ceux de la garde de version) donne « Wrong number of parameter bindings ».
- **Importer un fichier de test** depuis un autre rejoue ses tests : les fixtures (`makeLeg`) vont dans `lib/test/fixtures.ts`.
- **Contrat de Transitous vérifié** par une seule requête réelle : `/api/v5/plan`, `legGeometry.precision` = 6, `displayName` = « TER 17611 ».

## Revue

- **Important, corrigé** :
  - mentions d'attribution d'ORS et de Transitous absentes, alors que leurs politiques les exigent : ajoutées à la carte ;
  - le point d'une étape ou d'un séjour changé laissait des trajets faux : les trajets calculés sont retirés, ceux saisis à la main gardés (2 tests) ;
  - URL de base avec chemin (Transitous, Geoapify, Photon).
- **Laissé ouvert, noté dans la spécification** :
  - le dépôt doit être public et `CONTACT_URL` défini avant d'utiliser Transitous en production ;
  - un dossier replié masque ses tuiles ;
  - la reprise n'est pas stockée ;
  - les couleurs des tracés ne suivent pas un changement de thème tant que les trajets ne changent pas.
